## Task 3 — Design-Overhaul: Scroll-Effekte, Card-Effekte, Polish

**Files:** `src/styles/global.css`, `src/layouts/Base.astro` (oder ein kleines Inline-Script), `src/components/ProjectCard.astro`, `src/pages/[lang]/index.astro`, weitere Seiten nach Bedarf.

Ziel: Die Seite fühlt sich lebendiger und hochwertiger an, bleibt aber schnell, dependency-frei und barrierearm.

1. **Scroll-Reveal:** Sections und Cards faden/sliden beim Scrollen ein (IntersectionObserver setzt eine Klasse; CSS macht opacity/translate-Transition, gestaffelt via transition-delay oder CSS-Custom-Property pro Karte). Muss ohne JS funktionieren (Inhalte per Default sichtbar, JS fügt die Hidden-Klasse hinzu — kein FOUC, kein unsichtbarer Content bei deaktiviertem JS). Ein kleines Inline-Script in Base.astro genügt.
2. **Card-Hover:** Projekt-Cards bekommen einen deutlichen Hover: Lift (translateY), stärkerer Schatten, Akzent-Border, sanfte Transition. Optional ein subtiler Glow/Spotlight-Effekt. Kein 3D-Tilt-Overkill.
3. **Card-Press:** Aktiv-Zustand (`:active`) mit kurzem Scale-Down als Klick-Feedback.
4. **Hero-Polish:** dezenter Einstiegs-Effekt (z. B. Fade-in-up beim Laden, Porträt mit feinem Akzent-Ring/Glow on hover), Tags/Skills mit Hover-Feedback.
5. **Allgemeiner Polish:** nach eigenem Urteil — z. B. Section-Titles, Links, Buttons, Fokus-Zustände konsistent verfeinern. Keine Palette-Änderung, kein Layout-Umbau.
6. Reduced-Motion: alle neuen Effekte respektieren `prefers-reduced-motion` — insbesondere darf Scroll-Reveal Inhalte dann nicht ausblenden (Observer-Script bei reduced motion gar nicht erst aktivieren reicht).
7. Verifikation: `npm run build` grün, `npm run shots` läuft durch; 2–3 Desktop-Screenshots im Report referenzieren als Sichtprüfung (Dateipfade unter screenshots/).
